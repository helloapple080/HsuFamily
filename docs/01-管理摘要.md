# 許氏入口網管理摘要

## 一句話結論

目前專案已具備明確的**企業級工程思維**：採分層架構、預設授權、安全 Cookie、CSRF、防暴力破解、Refresh Token 輪替、最小資料庫權限、容器化與自動化測試；但若要宣稱「企業正式上線就緒」，仍必須完成部署環境、供應鏈修補與組織治理項目。

> **2026-07-24 自檢更新：** 最新 dependency audit 已發現 Next.js 16.2.2、Axios 1.14.0 的 High advisories，且 production compose 仍可能以 HTTP + 非 Secure Cookie 被誤用。完整證據與修復順序請以 [Skills 全面自檢報告](./07-Skills全面自檢報告.md) 為準；完成 P0 前不建議公開上線。

## 長官需要知道的成果

| 面向 | 改善前的主要問題 | 現況 |
|---|---|---|
| 帳號安全 | Token 可被前端腳本讀取 | 改為 HttpOnly Cookie，降低 XSS 竊取風險 |
| 交易安全 | Cookie 請求可能遭跨站偽造 | 所有寫入 API 全域驗證 CSRF token |
| 登入工作階段 | Refresh Token 明文且重放難以發現 | 僅存雜湊、輪替、token family 重放撤銷 |
| 即時通知 | 匿名使用者可能連線 | SignalR Hub 強制授權 |
| 資料庫 | 對主機開放且使用高權限帳號 | 不公開 port、應用帳號僅有單一 DB readWrite |
| 秘密管理 | 開發密碼與 JWT secret 曾寫入設定 | 已移除；首次啟動必須外部注入 |
| 供應鏈 | 部分套件與映像使用浮動版本 | 關鍵 IdentityModel 與 Docker image 固定版本 |
| 品質驗證 | 缺乏安全回歸測試 | GitHub Actions 自動 build、lint、test、production build |

## 可以做出的管理判斷

目前適合作為「有治理基礎、可持續強化」的正式專案基線，而不是臨時 Demo。原有認證 Critical／High 已處理，CI 已通過；但最新供應鏈 High 與 production deployment 預設仍需先修復，CI 綠燈不能單獨代表安全。

## 上線前必須核准的五件事

1. 正式 HTTPS 與 reverse proxy 設定，`COOKIE_SECURE=true`。
2. JWT、MongoDB、管理員密碼放入 Secret Manager，建立輪替責任人。
3. MongoDB 備份、還原演練及復原時間目標。
4. 集中式日誌、監控、告警與事故通報流程。
5. 依賴弱點掃描、權限盤點與定期滲透測試。

## 最終評級

- 企業級工程思維：**已具備**。
- 程式碼安全基線：**已建立，但最新依賴修補未通過**。
- 正式生產環境認證：**尚需部署與治理驗收**。
