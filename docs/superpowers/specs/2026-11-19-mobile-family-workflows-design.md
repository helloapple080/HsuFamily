# 手機優先與到期資訊

- 手機在底部提供四個常用入口；頂部帳號選單保留主題與登出。桌面側欄不變。底部留出安全區，不能遮住捲動內容或鍵盤焦點。
- 家用備忘用獨立編輯視窗，標題先取得焦點、不自動叫出鍵盤；內容可捲、操作列固定在表單底部。說明優先，可選擇加入上次處理日和下次到期日。手機搜尋與分類不擠在同一列。
- 上次處理日、下次到期日可為空；國曆日期依台北日曆日比較。讓有到期日的項目先依日期排列，逾期與七日內有明確文字；未排日期維持最近更新排序。只做站內提示，不寄信、不推播。
- 拜拜頁直接顯示台北今日起最近一日及同日規則；檢查當年和隔年，沿用既有農曆規則，不受年度列表篩選影響。
- D1 新增兩個可空欄位，舊資料不改。未傳日期的舊版更新保留既有日期；可用明確的 null 清空。既有授權、版本與停止收費的部署邊界不變。
- 家人登入驗收須有一個核准、可收信的信箱。尚未核准前不改 Access 白名單、身分提供者、正式資料或服務方案。

## 設計與驗證準則（2026-11-19）

- 以本機 Impeccable 4.0.2 的響應式指引和 [Vercel 當日公開規範](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md)檢查觸控區、焦點、鍵盤操作與避免水平溢出。[Impeccable 上游 4.9.2](https://github.com/pbakaus/impeccable/releases/tag/cli-v4.9.2) 與 [Superpowers 上游 v7.0.2](https://github.com/obra/superpowers/releases/tag/v7.0.2) 已核對；本機 `brainstorming` 與上游不同，本次不改全機 skills。
- 用專案內的農曆規則處理跨年與閏月。獨立程式審查發現舊分頁的嚴格格式驗證和 iPhone 鍵盤遮擋風險；相容性改由 API 能力標頭協商，表單依可視視窗調整。Chrome 模擬及自動測試不代替 iPhone／Android 真機驗收。
