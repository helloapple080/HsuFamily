# 部署與維運手冊

## 適用範圍

本手冊描述 repository 提供的安全部署基線。它不是正式環境認證；真正上線仍需把網域、憑證、proxy、secrets、備份與監控證據附在 release record。

## 必要秘密與設定

| 設定 | 正式環境 | 原則 |
|---|---|---|
| `MONGO_ROOT_PASSWORD` | 必填 | 只供 DB 初始化／管理，不給 app |
| `MONGO_APP_PASSWORD` | 必填 | `familyportal_app` 的單 DB 密碼；URI 特殊字元須符合部署契約 |
| `JWT_SECRET_KEY` | 必填 | 至少 32 字元，建議隨機 256-bit 以上 |
| `ADMIN_PASSWORD` | Compose 範本必填 | App 只在尚無 Admin 時呼叫 candidate factory／hash；現行 Compose 仍要求環境變數 |
| `PORTAL_DOMAIN`／`API_DOMAIN` | 必填 | 不含 scheme／path；由 Caddy 與 app 組合 |
| `CADDY_PROXY_IP` | 必填 | 必須落在 `FAMILY_PORTAL_SUBNET` 且與 Caddy 固定 IP 相同 |
| `ALLOWED_HOSTS` | 必填 | 只列 API 正式 host，不可 `*` |
| Data Protection keys | 必須持久化 | `data_protection_keys` volume，不可隨 container 消失 |

禁止提交 `.env`、token、JWT、MongoDB 密碼或管理員密碼。正式 secrets 應由平台 Secret Manager 注入；`.env.example` 只說明名稱與格式。


### xUnit v3／MTP 注意事項

- `global.json` 指定 `Microsoft.Testing.Platform`。
- 測試專案使用 `xunit.v3.mtp-v2` 與 `coverlet.MTP`。
- 必須使用 `dotnet test --project ...`；CI 再加 `--minimum-expected-tests 150`，避免 0 tests 假綠。
- CI 產生 Cobertura 並上傳 `backend-coverage-cobertura`；缺少 artifact 應使 job 失敗。

### AppleDouble 注意事項

專案位於 USB／macOS volume，可能產生 `._*`。`.gitignore`、Vitest 與 architecture source guard 均已排除；不得把 sidecar 加入 Git，也不得把它計為測試檔或程式碼。

## Development 啟動

`docker-compose.yml` 明確使用 Development：API／Frontend 只綁 loopback，MongoDB 不發布 port，Cookie Secure 關閉只供 localhost。不得把此檔直接當 production 公開部署。

## Production 啟動

1. 建立正式 DNS，令 `PORTAL_DOMAIN`／`API_DOMAIN` 指向主機。
2. 在 Secret Manager 建立所有必要 secrets；先執行 `docker compose -f docker-compose.production.yml config` 檢查插值。
3. 設定固定 Docker subnet 與 `CADDY_PROXY_IP`。
4. 啟動 MongoDB；等待 health check。
5. 執行冪等 `mongodb-user-init`，確認 app user 只有 FamilyPortal DB `readWrite`。
6. 啟動 Backend；Production 驗證會拒絕非 Secure Cookie 或非 HTTPS origin。
7. 啟動 Frontend 與 Caddy；只有 Caddy 發布 `80/443`，API／Frontend 使用內網 `expose`。
8. 檢查 `/health/live`、`/health/ready`、登入、Admin/User RBAC、CRUD 與 SignalR。
9. 執行外部 TLS／headers scan，保存 image digest、基準 SHA、核准人與測試 artifacts。

## 啟動與資料安全

- Default admin 先查是否已有 Admin；只有需要新增時才讀取／驗證／hash bootstrap password。
- Insert 遇 duplicate-key 後會重查是否已有 Admin；若只是與非管理員 username／email 衝突，會 fail fast。
- MongoDB 既有資料不會被本輪 validation 批次重寫。
- 禁止 drop database、清空 collection、刪除 `mongodb_data`／`mongodb_config` volume。
- 索引與 app user 初始化採冪等流程；仍須先備份再做正式環境變更。

## CSP 與前端運行

- Next proxy 每個 request 產生 nonce；root layout 為動態 rendering。
- `script-src` 不允許 `unsafe-inline`；Framer Motion 所需 style attributes 暫由 `style-src-attr 'unsafe-inline'` 相容。
- Sonner CSS 改為同源載入，並用版本鎖定 patch 停用 runtime style injection；升級 Sonner 時必須重驗 CSP。
- Caddy 與 Kestrel 都限制 request body 為 1 MiB。

## 日常監控

| 面向 | 建議指標／告警 |
|---|---|
| Availability | live／ready、HTTP 5xx、Frontend render failure |
| Authentication | login failures、401／403、429、refresh replay、Admin bootstrap failure |
| Realtime | SignalR connected／reconnecting／disconnected、重連失敗率 |
| Performance | API p95／p99、Mongo latency、nonce SSR CPU／memory |
| Capacity | CPU、memory、disk、Mongo volume、Data Protection keys |
| Supply chain | Dependabot、CodeQL、Trivy、NuGet／pnpm audit |

## 備份與還原

- 備份必須加密、限制存取、與服務主機分離並有保留政策。
- 至少每季執行還原演練，記錄耗時、資料筆數／雜湊與功能 smoke test。
- 由業務核定 RPO／RTO；只有 backup 沒有 restore 證據，不能判定為可復原。

## 事故處理

1. 凍結變更，建立時間線並保存 logs／artifacts。
2. JWT 疑似外洩：輪替 secret，使 access tokens 失效。
3. Refresh 疑似外洩：撤銷 token family 或全部 sessions。
4. DB secret 疑似外洩：先輪替 app password，再查權限與存取紀錄。
5. Supply-chain advisory：判斷 reachability、先升級與重驗，不用「目前沒用到」取代修補。
6. 修復後重跑 `158+` backend gate、frontend tests／lint／build、audits 與 smoke test，完成事後報告。
