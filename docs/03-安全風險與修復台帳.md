## 已建立的縱深防禦

- 預設授權：未標示 `[AllowAnonymous]` 的 endpoint 一律需要登入。
- RBAC：Admin CRUD 使用 `AdminOnly` policy。
- 密碼：只使用 Argon2id，不保存或記錄明文。
- Session：短效 access token、refresh rotation、重放撤銷。
- Web：HttpOnly、SameSite、Secure、CSRF、CORS allowlist、安全 headers。
- Abuse：一般 API、login、refresh 分層 rate limit。
- Database：網路隔離、最小權限、索引初始化。
- Runtime：非 root container、持久化 Data Protection keys、健康檢查。
- SDLC：版本固定、CI build／lint／test、結構化安全台帳。

## 尚存與接受中的風險

| 風險 | 原因 | 正式環境處置 | Owner 建議 |
|---|---|---|---|
| TLS 與 proxy 拓撲未知 | 本機專案無實際網域 | HTTPS termination、HSTS、KnownProxies、Cookie Secure | 維運／平台 |
| Secrets 生命週期 | Repo 不應保存正式秘密 | Secret Manager、90 天輪替、緊急撤銷流程 | 平台／資安 |
| CSP 允許 inline script/style | Next hydration 相容需求 | 導入逐請求 nonce 並移除 unsafe-inline | 前端／平台 |
| Mongo 備援未驗證 | 沒有正式資料量與 RTO/RPO | 排程備份、加密、異地保存、還原演練 | DBA／維運 |
| 缺少完整真實瀏覽器 E2E | 本機缺少完整可啟動環境 | CI 建立 Mongo/API/Web test stack，驗證 login-refresh-logout | QA／開發 |
| 可觀測性與事故治理 | 需企業平台支援 | Metrics、tracing、集中 log、alert、runbook、演練 | SRE／維運 |
| AuthController 業務邏輯偏重 | 可維護性而非直接漏洞 | 將登入與 rotation 移至 Application Service | Backend |
